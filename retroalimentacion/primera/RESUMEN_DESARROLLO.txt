1. DESCRIPCION GENERAL
--------------------------------------------------------------------------------
Aplicacion web interna para gestionar el proceso de reclutamiento y seleccion
de personal de LARCO (denominada "LARCO ATS" - Applicant Tracking System).

El sistema cubre el ciclo completo:
  Requerimiento de personal -> Importacion de CVs (Hojas de Vida) ->
  Embudo de seleccion (kanban por fases) -> Entrevistas ->
  Verificacion de antecedentes (scraping de portales oficiales) ->
  Evaluacion por proveedor externo -> Historial y auditoria.

Estado actual: FUNCIONAL y EN PRODUCCION LOCAL (maquina Windows).
Ingreso web activo y verificado end-to-end (22/10/2026).

2. STACK TECNOLOGICO
--------------------------------------------------------------------------------
BACKEND
  - Framework   : NestJS 11 (Express 5) - TypeScript 5.8
  - Base datos  : PostgreSQL 17 (puerto 5433) - SQL crudo via pool `pg`
                  + TypeORM SOLO para el modulo de requerimientos
  - Auth        : JWT Bearer (@nestjs/jwt + passport-jwt) + bcryptjs (cost 12)

  - Tailwind CSS 4 (@tailwindcss/vite)
  - react-router-dom 7 (enrutamiento SPA)
  - zustand 5 (estado global, sesion persistida en localStorage)

  - @dnd-kit + @hello-pangea/dnd (kanban drag & drop)
  - lucide-react (iconos), date-fns (fechas)

3. ARQUITECTURA Y FLUJO
--------------------------------------------------------------------------------
  Navegador (SPA React)
        |
        |  http://localhost:3001  (un puerto solo: backend sirve frontend)
        |  o http://localhost:5173 (dev Vite, proxy /api -> 3001)
        v
  Backend NestJS (puerto 3001, prefijo global /api)
        |  - JWTAuthGuard en 9 de 10 modulos (login es publico)
        |  - Cifrado AES-256 de PII de candidatos (reutiliza JWT_SECRET)
        v
  PostgreSQL 17 (puerto 5433, base: gestion_humana_ats)

RUTA DEL INGRESO WEB (flujo verificado):
  /login -> POST /api/auth/login -> AuthService.validateUser
    -> SQL usuarios JOIN roles (activo=true) + bcrypt.compare
    -> firma JWT (payload {sub, email}, expira 24h)
    -> useAuthStore.login() persiste en localStorage ('larco-auth')
    -> navigate('/') -> ProtectedRoute deja pasar
  Cada request: axios inyecta 'Authorization: Bearer <token>'
  Si 401: logout automatico y redireccion a /login

5. MODULOS DEL BACKEND (10) - TODOS BAJO PREFIJO /api
--------------------------------------------------------------------------------
Todos los controllers aplican @UseGuards(JwtAuthGuard) a nivel de clase,
EXCEPTO el login (unico endpoint publico).

2.1 AUTH (publico en login)
    POST   /api/auth/login          Login (email+password -> JWT + user)
    GET    /api/auth/profile        Perfil del usuario autenticado

2.2 CANDIDATOS
    GET    /api/candidatos          Listado (filtros en query)
    GET    /api/candidatos/:id      Detalle (descifra PII AES-256)
    POST   /api/candidatos          Alta (soporta CV adjunto)
    PATCH  /api/candidatos/:id      Edicion
    GET    /api/candidatos/:id/historial  Historial del candidato

2.3 EMBUDO (kanban de seleccion)
    GET    /api/embudo/etapas          5 fases del embudo
    GET    /api/embudo/candidaturas    Candidaturas con position
    GET    /api/embudo/dashboard       Metricas del dashboard
    POST   /api/embudo/mover-fase      Mover candidato de fase
    POST   /api/embudo/crear-candidatura  Crear candidatura

2.4 ANTECEDENTES (scraping Playwright - Policia Nacional, SIMIT, etc.)
    GET    /api/antecedentes/candidato/:id         Historial de consultas
    POST   /api/antecedentes/consultar/:candidatoId  Disparar consulta
    GET    /api/antecedentes/estado/:consultaId    Estado del scraping

2.5 ENTREVISTAS
    GET    /api/entrevistas                Listado
    GET    /api/entrevistas/candidatura/:id Por candidatura
    POST   /api/entrevistas                Crear
    PATCH  /api/entrevistas/:id            Editar/actualizar resultado
    DELETE /api/entrevistas/:id            Eliminar

2.6 PROVEEDOR (evaluacion por terceros)
    GET    /api/proveedor/candidatura/:i  Resultados por candidatura
    POST   /api/proveedor                 Registrar resultado
    PATCH  /api/proveedor/:id             Actualizar resultado

2.7 HISTORIAL Y AUDITORIA
    GET    /api/historial/candidato/:id   Historial completo de un candidato
    GET    /api/historial/auditoria       Logs de auditoria (tabla inmutable por trigger)
    GET    /api/historial/rechazos        Historial de rechazos (motivo obligatorio)

2.8 REQUERIMIENTOS (TypeORM - unico modulo con ORM)
    GET    /api/requerimientos            Listado
    GET    /api/requerimientos/estadisticas  Metricas
    GET    /api/requerimientos/:id        Detalle
    POST   /api/requerimientos            Crear
    PUT    /api/requerimientos/:id        Editar
    DELETE /api/requerimientos/:id        Eliminar

2.9 UPLOADS
    POST   /api/uploads                   Subir archivo (entidad + id)
    GET    /api/uploads/:entidad/:entidadId  Listar adjuntos

2.10 IMPORTACION (carga masiva de HVs)
    POST   /api/importacion/parse-pdf       Parsear un PDF (pdf-parse)
    POST   /api/importacion/importar-cvs    Importar lote de CVs
    GET    /api/importacion/pdf/:filename   Descargar PDF original
